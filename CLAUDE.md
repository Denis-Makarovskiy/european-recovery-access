# Рабочий контракт проекта European Recovery Access

Этот файл обязателен для всех сессий и всех субагентов проекта. При конфликте с любым другим документом пакета (`01`–`07`) в части *процесса* приоритет у контракта; в части *содержания продукта* приоритет у документов `01`–`07`.

## 1. Принцип экономии токенов

Токены — ограниченный ресурс проекта. Базовое правило: **минимальный объём контекста, достаточный для правильного результата.**

Обязательно:

- Читать только те файлы и те их части, которые нужны для текущего шага. Не загружать пакет `01`–`07` целиком, если задача касается одной секции.
- Не перечитывать файл, который уже прочитан или только что изменён.
- Не пересказывать в ответе содержимое файлов, которое пользователь и так может открыть; давать ссылку `путь:строка`.
- Не дублировать спецификацию в промпте субагента — передавать ссылки на файлы плюс только дельту (что именно сделать, чего избегать, критерий готовности).
- Бинарные и крупные ассеты (PNG, изображения) не читать как изображение без явной необходимости; хватает метаданных (`file`, `sips -g`).
- Один субагент — одна законченная задача. Не дробить на десяток микро-агентов: каждый запуск оплачивает холодный старт контекста.
- Не запускать параллельные агенты, которые заново выводят один и тот же контекст.
- Не использовать workflow / multi-agent оркестрацию без явной просьбы пользователя.

Запрещено:

- Спекулятивное расширение объёма работ («заодно сделаю ещё»).
- Повторное обсуждение уже принятых решений.
- Длинные отчёты о процессе. Отчёт = что сделано, что не сделано, что дальше.

## 2. Разделение моделей

### Старшая модель (Opus, основная сессия)

Делает то, что требует глубокого рассуждения и ответственности за решение:

- Планирование и декомпозиция задач.
- Архитектурные и продуктовые решения, выбор компромиссов.
- Формулировка ТЗ для субагентов и критериев приёмки.
- Проверка и приёмка результата (ревью кода, соответствие спецификации, соответствие ограничениям из `01-product-brief.md`).
- Работа с юридически и этически чувствительным содержанием: медицинские формулировки, обещания результата, отзывы, метрики, приватность и обработка данных лида.
- Разрешение противоречий между документами пакета.

Старшая модель **не пишет код руками**, кроме правок в один-два файла, где постановка задачи субагенту дороже самой правки.

### Sonnet 5 (фоновый субагент)

Делает всю техническую работу:

- Реализация компонентов, секций, страниц, API-роутов.
- Конфигурация проекта: Next.js, TypeScript, Tailwind, ESLint, env-файлы.
- Перенос токенов из `design-tokens.json` в конфиг темы.
- Перенос копирайта из `05-content-en.md` в `lib/content.ts`.
- Рефакторинг, тесты, исправление ошибок сборки и типов.
- Прогон линтера, сборки, Lighthouse и правки по их результатам.

Запуск: инструмент `Agent`, `model: "sonnet"`, `run_in_background: true`.

Формат постановки задачи субагенту:

1. Ссылки на файлы спецификации (не их содержимое).
2. Точный список файлов, которые агент создаёт или меняет.
3. Ограничения (токены, а не хардкод; без выдуманных отзывов и метрик; a11y AA).
4. Критерий готовности: сборка проходит, типы проходят, линтер чистый.

Приёмка результата субагента — всегда за старшей моделью. Результат фонового агента не считается готовым, пока он не проверен.

## 3. Продуктовые ограничения (не нарушать ни на одном уровне)

- Никаких выдуманных отзывов, историй клиентов, процентов успеха и гарантий выздоровления.
- Никаких утверждений про госпитализацию «за 24/48 часов».
- Сервис — независимый координатор размещения, не клиника и не экстренная служба; дисклеймер обязателен.
- ПДн и клинические данные не уходят в аналитику.
- Числовые метрики в секции «Why Trust the Process» публикуются только если операционно подтверждены; иначе — качественные формулировки.
