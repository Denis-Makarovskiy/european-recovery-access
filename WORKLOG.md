### Перенос на GitHub Pages и приём заявок в Telegram (Sonnet 5 ×2, приёмка Opus)
Сайт переведён на статический экспорт: `output: "export"`, `basePath` из `NEXT_PUBLIC_BASE_PATH`, `.nojekyll`, деплой через GitHub Actions на push в `main`. `next/image` работает без серверного оптимизатора на заранее собранных AVIF/WebP.

`app/api/lead/route.ts` и `lib/rate-limit.ts` удалены — POST-роут в статике не собирается. Их заменил Cloudflare Worker в `worker/`: та же Zod-схема (копия, требует ручной синхронизации с `lib/validation.ts`), honeypot, лимит 5 запросов за 10 минут на IP с опциональным KV, доставка в Telegram с HTML-экранированием, необязательный дублирующий webhook. Токен бота живёт в секретах Cloudflare.

Добавлено при приёмке:
- Запрос с чужого Origin теперь отклоняется с 403. Раньше проверка Origin влияла только на заголовки CORS — браузер не смог бы прочитать ответ, но заявка с чужого сайта всё равно улетела бы в Telegram.
- `worker` исключён из корневых `tsconfig.json` и `eslint.config.mjs` — у него свой рантайм и свои типы.

Проверено вживую на `wrangler dev`, а не по отчёту агента: чужой Origin 403, разрешённый проходит, honeypot 400, заявка без контактов 400, GET 405, preflight 204 с корректным `Access-Control-Allow-Origin`, лимит срабатывает ровно после пятого запроса. В логах только редактированная сводка — ни имени, ни телефона, ни почты.

Не проверено без реального деплоя: доставка и вёрстка сообщения в живом чате Telegram, поведение KV под нагрузкой, работа лимита между колокациями Cloudflare.

Риск, требующий решения: эндпоинт публичный, и CORS не защищает от прямых POST мимо браузера. Лимит и honeypot отсекают примитивный спам, но от ботнета не спасут. Нормальное решение — Cloudflare Turnstile перед отправкой формы.
